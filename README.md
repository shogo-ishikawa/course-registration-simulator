# 日本大学生産工学部 履修登録シミュレータ

GitHub Pagesで公開できる静的Webアプリです。ZIPを展開した直下のファイルを、そのままGitHubリポジトリへpushしてください。

## まず公開する

1. GitHubで空のリポジトリを作成します（例: `course-registration-simulator`）。
2. このフォルダの中身をリポジトリへ入れます。
3. ターミナルで次を実行します。`YOUR_NAME` と `YOUR_REPOSITORY` は自分の値へ置き換えてください。

```bash
git init -b main
git add .
git commit -m "Initial release"
git remote add origin https://github.com/YOUR_NAME/YOUR_REPOSITORY.git
git push -u origin main
```

4. GitHubのリポジトリで `Settings` → `Pages` を開きます。
5. `Build and deployment` の `Source` を **GitHub Actions** にします。
6. `Actions` タブの「GitHub Pagesへ公開」が成功すると、PagesのURLで利用できます。

リポジトリ名にかかわらず動作するよう、画像・JavaScript・CSSのパスは相対指定です。以後は `main` へのpushごとに自動で検証・公開されます。

## 学生の時間割を端末へ保存する

- 編集内容はブラウザのローカルストレージへ自動保存されます。
- 「端末に保存」を押すと、履修計画をJSONファイルとしてダウンロードできます。
- 「保存データを読み込む」から、そのJSONを別のブラウザや端末で復元できます。
- プライバシー保護のため、ダウンロードするJSONには学籍番号を含めません。

## 組んだ時間割を出力する

時間割上部の出力形式で「Excel」または「CSV」を選び、「時間割を出力」を押すと、選択した
全科目をファイルとしてダウンロードできます。学期、開講期間、講義コード、科目名、曜日時限、
担当教員、キャンパス、教室、単位数、必修・選択区分を出力します。学籍番号は含みません。

- 出力形式で「PDF」を選ぶと、1Q〜4Qまたは前期・後期の範囲を指定して直接PDFをダウンロードできます。
  A4横向きで各Qを1ページに分け、科目名・キャンパス・教室・担当教員名を掲載します。学籍番号は含みません。
  このPDFは見た目を保つための画像形式で、文字の検索・選択はできません。文字を選択できるPDFが必要な場合は「印刷・PDF保存」を利用してください。
- 「画像保存・印刷」は最初は折りたたまれています。見出しを押して開くと1Q〜4Qの出力対象を選べます。画像形式はPNG・JPEGです。
  閉じても出力条件と作成済みプレビューは維持されます。
- 壁紙サイズはPC向け1920×1080／2560×1440、スマホ向け1080×1920／1080×2400です。
  「画像を保存」でダウンロードし、生成後のプレビューから再保存・スマホでの長押し保存もできます。
- 「スマホへ共有」は選択したQ・サイズ・画像形式を共有メニューへ渡します。共有非対応の場合は画像をダウンロードします。
- 画像・印刷には科目名、キャンパス、教室、担当教員名を載せます。長い教室・担当は画像下部の番号付き詳細欄へ全文を表示し、省略しません。
- 「印刷」は1Q／2Q／3Q／4Qまたは前期／後期を選べます。A4横向きでQごとにページを分けます。
  前期・後期では2つのQを別々の表として印刷します。印刷画面からPDF保存も可能です。
- 通年科目は登録先の学期を反映し、集中講義・曜日時限未定の科目は週の表とは別欄に記載します。
  土曜や6限以降の登録があれば出力に含めます。画像にすべての情報が収まらない場合は、切り捨てずエラーを表示します。
- 「メールで送信」は前期・後期の時間割を本文にしたメール作成画面を開きます。

## Boxの時間割Excelを自動反映する

`.github/workflows/refresh-timetable.yml` が、既定では毎日 **日本時間6:17** に次のURLを確認します。

<https://nihon-u.box.com/s/14vswxrknmmi2z06xa3xcjnfl6h8jt8d>

ExcelのSHA-256が前回と違う場合だけ、科目データを作り直して `main` へ自動コミットします。そのコミットをきっかけにGitHub Pagesも再公開されます。

安全のため、次のチェックを通らないデータは公開しません。

- ダウンロード結果がExcel形式であること
- 必要な列と「学部」シートがあること
- 抽出科目数が急減していないこと
- 講義コードの重複や曜日時限の異常がないこと
- アプリ全体が本番ビルドできること

Box側では、共有リンクを「リンクを知っている全員」かつ「閲覧およびダウンロード可」にしてください。ダウンロードが禁止されている場合、更新処理は失敗しますが、公開中のデータは変更されません。

## 時間割表のURLを変更する

コード編集は不要です。

1. GitHubリポジトリの `Settings` → `Secrets and variables` → `Actions` を開きます。
2. `Variables` タブで `New repository variable` を押します。
3. Nameを `TIMETABLE_XLSX_URL`、Valueを新しい共有URLにして保存します。
4. すぐ確認したい場合は `Actions` →「時間割データを定期更新」→ `Run workflow` を実行します。

年度も変わる場合は、同じ場所に `TIMETABLE_ACADEMIC_YEAR`（例: `2027`）を追加・更新してください。`Run workflow` の入力欄へ一時的なURLや年度を入れて、設定前に試すこともできます。

Boxの共有画面URLでも、更新処理が `download=1` を付けてファイル本体の取得を試みます。組織の設定で直接取得できない場合は、Boxの「リンク設定」に表示されるExcelの直接リンクを `TIMETABLE_XLSX_URL` に指定してください。

> GitHubの仕様上、公開リポジトリで60日間リポジトリ活動がないと、定期実行が自動で無効になる場合があります。`Actions` タブで「時間割データを定期更新」が有効か、学期開始前に確認してください。

## Boxを確認する頻度を変更する

GitHubリポジトリの `Settings` → `Secrets and variables` → `Actions` → `Variables` で、
Repository variable `TIMETABLE_CHECK_INTERVAL_HOURS` を追加してください。設定できる値は
`0.25`, `0.5`, `1`, `2`, `3`, `4`, `6`, `8`, `12`, `24`, `48`, `72`, `168`, `672`, `674`
（時間）で、未設定時は `24` です。`0.25` は15分、`0.5` は30分間隔です。
`168` にすると毎週月曜日の日本時間6:17、`24` にすると毎日6:17を基準に確認します。
4週間ちょうどの間隔は `672` 時間です。手動設定済みの `674` も互換性のため使用できますが、
これは4週間と2時間の間隔になります。
履修登録期間は `1` や `3`、それ以外は `168` へRepository variableを変更する運用ができます。
手動の `Run workflow` は頻度設定にかかわらず常に確認します。

## 更新履歴を追加する

BoxのExcelに変更があり、科目データへ正常に反映された場合は「時間割表を更新」という履歴が
自動追加されます。手動の履歴は次のコマンドで追加できます。

```bash
npm run history:add -- --message "検索画面の説明を改善"
```

日時を指定する場合は `--date "2026-08-08T12:00:00+09:00"` も追加できます。生成された
`src/data/update-history.json` を他の変更とともにコミットしてください。履歴はトップ画面の
「最近の更新」と「更新履歴」ボタンから、`[YYYY年MM月DD日 HH:MM] 更新内容`
の形式で確認できます。

更新履歴の時刻は日本時間に変換し、秒を表示せず1分単位の `HH:MM` で表示します。
自動更新では、時間割データの最終取込日時と更新履歴に同一の時刻を記録し、検証時にも両者が
一致することを確認します。

## 学科別資料とクラス分け表

学科を選択すると「時間割作成用資料掲載サイト」と「クラス分け表で正しいクラスか確認する」
が、その学科の公式ページへ切り替わります。資料は2026年度・1年生向けです。
資料リンクの見出しは16px、学科名は20px相当に拡大しています。2～4年生ではURLを持たない
無効なボタンとなり、マウス・キーボード・右クリックからも開けません。1年生に戻すと再び利用できます。
クラスを選択した後にも確認ボタンを表示し、公式表を開いて照合した学生が「確認済み」を
チェックできます。学籍番号・学科・学年・学期・時間割の選択変更、ページの再読み込み時には
再確認が必要です。ボタンを押すだけで確認済みにはしません。

### 自動判定と開講クウォーター

2026年度の9学科の公式PDFを確認し、431講義の対応を取り込みました。
科学基礎実験A・B／工学基盤実験A・Bは、全9学科・144講義で学籍番号別の開講Qに対応しています。
候補・変更候補・選択済みカードに「3Q」「4Q」などを表示します。
キャリアデザインは今回のPDFに指定がないため、Qを確認して手動で選択します。

`src/data/department-guidance.json` の `rules` に科目ごとの番号範囲と講義コードを保存し、
`verifiedAt`・原本ファイル名・SHA-256・PDFページを記録しています。
縦の「〜」を含む明示範囲は両端を含み、列挙された番号は連続部分だけを圧縮し、欠番を補いません。
氏名・成績・原本PDFは公開リポジトリに含めません。
確認した資料・保留箇所は [クラス分け表の取込記録](docs/class-guidance-sources.md) を参照してください。

自動判定は対象年度・学年・学籍番号全体を照合し、通年で一意に対応する講義を確定してから
現在の学期と別学期に振り分けます。公式表で別学期を指定された未選択科目は、今期の候補から外し、
指定学期とQを表示します。同じ科目を別学期で選択済みの場合も再候補化しません。
実験AとB、科学基礎と工学基盤はそれぞれ別科目です。履修計画上の選択のみを参照し、単位取得を判定しません。
今期の手動選択は残し、公式指定と異なる場合は警告します。削除すると指定学期で再選択できます。

コース条件や原表内の年度・時限の矛盾は推測で解決せず、手動確認を残しています。
複数候補、古い講義コード、担当教員・教室・キャンパスや時間の変更を検出した科目も手動確認に戻します。
学籍番号の末尾だけや、候補の並び順からクラスを推定することはありません。
「必修を自動配置」は所属学科・設置学年の必修定義だけを対象とします。クラス分け表に載っていても、選択科目は自動追加しません。
学籍番号を修正して押し直すと、配置済みの必修も確認済みの指定クラス・開講Qへ更新します。別学期への移動も含みます。
差し替える必修をまとめて競合検査し、競合時は元の計画を保持してエラーを表示します。手動で追加した選択科目は保持します。
旧保存データで必修扱いになっていた選択科目は自動配置時に除外し、その科目名と再追加方法を表示します。
手動のクラス変更・削除は引き続き可能ですが、自動配置を押し直すと確認済みの必修指定クラスが優先されます。変更後は公式表を再確認してください。

微分積分学・情報リテラシー・化学など、実験以外の科目も同じ公式表の対応を使います。
選択科目の微分積分学IIなどは「クラス分けのある選択科目」、時間割の空きコマ、科目詳細から
追加できます。追加画面では学籍番号に対応するクラスを初期選択し、開講Q・担当教員・講義コードを表示します。
履修するかは学生が決め、追加を確定するまでは時間割を変更しません。キャンセルしても選択状態は変わりません。
指定Qが別学期の場合もそのクラスを初期選択し、確定後は該当学期・Qの時間割へ移動します。
全Qの別クラスを手動選択でき、追加後の「クラス変更」は現在の手動選択を保持して開きます。
重複やキャンパス間移動は追加・変更時に再判定し、衝突時は元の時間割を維持します。
選択科目にも公式表の確認と、変更後の自己確認解除を適用します。通年・集中講義は従来の専用登録方式を使用します。

後期の微分積分学Iは必修の自動配置から除外します。前期に履修して単位を取得できなかったことを学生自身が確認した後、再履修欄から手動追加してください。
前期のIと後期のIは、その再履修確認がある場合だけ同じ計画に保持できます。同じ学期の複数クラスは選べません。
再履修の確認は保存・書き出しせず、学籍番号・学科・学年の変更や読み込み、ページ再表示時に再確認を求めます。既存の後期Iは対象確認のエラーを表示し、勝手に削除しません。
CAP上限は1年生の前後期とも20単位です。旧保存データに22・24単位があっても20に補正します。緩和は2年生以上のみ選択できます。

学籍番号はクラス判定のため外部に送信しません。既存仕様どおりこの端末のブラウザには
保存されますが、ダウンロードする履修計画ファイルには含めません。
クラス分け表の内容は時間割Excelの自動更新とは別に確認・更新する必要があります。

## GitHubへ更新する運用

今後のサイト修正はGitHubへのpush、必要に応じたPR作成まで行います。
ZIPを利用者が展開して手動pushする運用は使用しません。

## 手元で確認する

Node.js 24以降を用意して、次を実行します。

```bash
npm ci
npm run check
npm run dev
```

本番用ファイルを作る場合は `npm run build`、ビルド結果を確認する場合は `npm run preview` を使います。

## 更新表示

画面上部にアプリのバージョン、アプリの最終更新日時、時間割データの最終取込日時と更新履歴を表示します。GitHub Pages上のアプリ更新日時は、公開対象コミットの日時から自動設定されます。

## 重要な注意

このアプリは履修計画を立てるための補助ツールです。実際の履修登録には反映されません。時間割を確認した後に、必ずポータルシステムから正式な履修登録を行ってください。
